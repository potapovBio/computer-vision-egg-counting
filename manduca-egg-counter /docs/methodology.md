# Методика и воспроизводимость

## Источники

Авторские тезисы: Г. А. Потапов, «Применение алгоритмов компьютерного зрения для автоматизации подсчёта яиц чешуекрылых на примере табачного бражника (Manduca sexta)». [PDF тезисов](publications/potapov-manduca-egg-counting.pdf) включён в репозиторий. [Карточка РИНЦ / eLIBRARY.RU](https://elibrary.ru/item.asp?id=89172412&pff=1).

Численные результаты проверены по `reports/train/results.csv`, строка `epoch=74`. Конфигурации в `reports/*/args.yaml` взяты из сохранённых экспериментов; абсолютный путь к данным заменён на переносимый. Это архивные конфигурации, а не результаты нового запуска.

В тезисах упомянуты повороты и изменения яркости. В сохранённой конфигурации `degrees=0.0`, `hsv_v=0.4`, `fliplr=0.5`, `mosaic=1.0`. Поэтому ненулевые повороты в этом запуске не подтверждены. Исторические зависимости не полностью зафиксированы; в локальном окружении найден Ultralytics 8.3.95. Побитовое воспроизведение обучения не гарантируется.

## Интерпретация качества

`B` в журнале означает bounding boxes, `M` — masks. mAP50 не измеряет ошибку итогового количества яиц. Для подсчёта нужна отдельная оценка числа предсказанных объектов относительно ручной разметки по каждой фотографии, например MAE и RMSE.

Эпоха 74 выбрана для таблицы как эпоха, указанная в тезисах и имеющая наибольший box mAP50 в сохранённом журнале. Это не подтверждение того, что `best.pt` соответствует именно эпохе 74: критерий выбора checkpoint может учитывать другие метрики. Хеш локально подготовленных весов находится в `reports/weights.json`.

## Аудит данных

Локальные YOLO-папки: 172/64 изображения, 11 670/3 561 объектов. COCO-экспорт: 186/50 изображений, 11 334/3 897 объектов. Общее число изображений и объектов одинаково, распределение между выборками отличается. Скрипт конвертации поддерживает автоматическое переразбиение, но причина конкретного изменения не установлена.

Точных побайтовых дубликатов файлов между локальными YOLO-папками не найдено. Похожие кадры одной сцены и биологическую независимость необходимо проверить отдельно. Не установлено, что папки данных не менялись после исторического обучения. Поэтому сохранённые метрики нельзя автоматически приписать текущему разбиению.

В исходном YAML `test` и `val` указывали на одну папку. В публикуемой конфигурации поля `test` нет: независимый тестовый набор не подтверждён.

## Демо и ограничения

Новый `predict.py` считает обнаружения единственного класса `egg`; при отсутствии объектов возвращает ноль. Скрипт проверяет входной файл и веса. `conf=0.4` сохранён по рабочему варианту Telegram-бота. `max_det=1000` выбран для плотных скоплений; историческая конфигурация валидации использовала 300. Это изменение демо, а не повторное измерение качества.

Бот использует отдельную временную папку для фотографии, читает токен из окружения и обрабатывает сообщения последовательно. Это демонстрационная версия; повторная загрузка модели на каждый запрос ограничивает производительность. Telegram-сжатие также может менять качество.

Для следующего исследования: выделить независимые сцены, измерить ошибку подсчёта, отдельно оценить плотные кладки и плохое освещение, затем подобрать порог уверенности.
